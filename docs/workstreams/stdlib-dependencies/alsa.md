## Your piece: Linux audio without alsa-lib

`src/stdlib/Audio/Linux/LinuxAudioDevice.btrc` (+ `Linux/Alsa.h`) is the Linux provider of `Library.Audio.AudioDevice`, written against alsa-lib (`native.pkg-config alsa` in `src/stdlib/Audio/btrc.toml`). alsa-lib is a distribution package, not the operating system. What Linux itself supplies is the kernel's ALSA interface: PCM and control character devices under `/dev/snd` driven by the ioctls in `<sound/asound.h>` (kernel UAPI headers). The sound server most desktops run (PipeWire, or PulseAudio) is a system service reachable over its socket.

Read first: the whole provider and `Alsa.h`, `AudioDevice.btrc`, `RealtimeAudio*.btrc`, `src/stdlib/Audio/README.md`, the Linux audio tests (`src/tests/native/audio/linux/`, the Python drivers that mention alsa: `grep -rln "alsa\|asound" src/tests tools nix docs`), and `nix/asound.conf` (the container has no sound card, so today's tests run against alsa-lib's `null` plugin as the `default` PCM).

Today the inventory offers the PCM names alsa-lib's hints list: `default`, `pipewire`, `pulse`, `jack`, `sysdefault:…`, `hw:…`, `plughw:…`. Those ids are public (programs store them).

### Build
1. **Kernel PCM backend** in BTRC (a small first-party header may include `<sound/asound.h>` and wrap ioctl request numbers and the structs' field access where BTRC cannot express them): enumerate cards and PCM devices from `/proc/asound/cards` + `/proc/asound/pcm` (or `SNDRV_CTL_IOCTL_CARD_INFO`/`PCM_NEXT_DEVICE`/`PCM_INFO` on `/dev/snd/controlC*`), open `/dev/snd/pcmC<c>D<d>{p,c}` non-blocking, `SNDRV_PCM_IOCTL_HW_REFINE`/`HW_PARAMS`/`SW_PARAMS`/`PREPARE`/`START`/`DROP`/`WRITEI_FRAMES`/`READI_FRAMES` (or mmap status/control if you need it for xrun detection: `SYNC_PTR`), `poll` for readiness with the same bounded waits the provider has now, xrun recovery (`-EPIPE` → prepare, reported as a discontinuity), suspend recovery (`-ESTRPIPE` → `RESUME`/prepare), capability probing (channels, rate range, period range) through `HW_REFINE` masks/intervals. `hw:C,D` ids keep their meaning (exclusive, the device's own formats — fail with `AUDIO_DEVICE_UNSUPPORTED_FORMAT` as before if float32 at the requested rate is not offered). `plughw:C,D` and `sysdefault:CARD=…` keep their ids by first-party adaptation: choose the best native format the hardware offers (FLOAT_LE, S32_LE, S24_3LE/S24_LE, S16_LE) and convert the provider's float32 in the realtime loop without allocation (channel count adaptation as alsa-lib's plug did for the cases the provider relies on: say which; no resampling — if the rate is not native, report unsupported and say this differs from alsa-lib's rate plugin).
2. **Sound-server backend** for `default`, `pulse` and `pipewire`: the PulseAudio native protocol over `$PULSE_SERVER` or `$XDG_RUNTIME_DIR/pulse/native` (served by PulseAudio and by PipeWire's pipewire-pulse), first-party: cookie auth (`~/.config/pulse/cookie`, `$PULSE_COOKIE`), tagstruct marshalling, `AUTH`, `SET_CLIENT_NAME`, `CREATE_PLAYBACK_STREAM`/`CREATE_RECORD_STREAM` with float32 samples and buffer attributes sized for low latency (tlength/minreq/fragsize from the requested period, `ADJUST_LATENCY`), stream data as memblocks on the socket (no SHM/memfd negotiation), `REQUEST` flow control, underflow/overflow notifications mapped to discontinuities, `GET_SERVER_INFO`/`GET_SINK_INFO_LIST`/`GET_SOURCE_INFO_LIST` for the default devices' channel counts and rates, drain/cork/close. Validate every length from the peer. If no server socket exists, `default` falls back to the first usable kernel device, as alsa-lib's default did on a system without a sound server.
3. `jack` cannot be reached without libjack (its transport is private shared memory): drop it from the inventory and say so in the report and README (JACK users on PipeWire are served by the `pipewire`/`default` entries).
4. Delete `Alsa.h`, the alsa binding and pkg-config record; remove the `alsa-lib` `[[pending]]` row; keep the public behaviour, statuses and frame accounting the provider's tests pin.

### Proving it — and what cannot be proven here
- The container has no `/dev/snd` and no sound server. Build two first-party test doubles: (a) a **fake PulseAudio-protocol server** (Python, in the test tree) that authenticates, accepts playback and record streams, paces `REQUEST`s by a clock, records what it was sent and can inject underruns, disconnects and malformed frames; (b) for the kernel backend, isolate the ioctl layer behind a seam small enough that a **fake PCM device** can stand in at the syscall boundary for tests (for example a provider-internal interface with a kernel implementation and a test implementation that models hw-params refinement, period wakeups, xruns and suspend) — the logic above the seam is then tested here through both frontends, plain and sanitized, and only the thin ioctl wrapper is untested.
- State plainly in the report that the kernel ioctl wrapper and real-server interoperability were not run here. Provide an opt-in test (skipped when `/dev/snd/pcmC*D*p` is absent or `BTRC_TEST_AUDIO_HARDWARE` is unset) that the integrator can run on a CI runner after `sudo modprobe snd-dummy` / `snd-aloop` (loopback lets it verify played samples come back on capture), and another that runs against a real `pipewire-pulse`/`pulseaudio` when present; give the exact commands.
- Update the existing Linux audio tests that depended on alsa-lib's null plugin and `nix/asound.conf` to use the doubles (list the `nix/`, flake and workflow lines the integrator must change), and assert with `DependencyAudit().binary_problems` that a built audio program imports no `libasound`.
- Report measured or reasoned latency differences: the old `default`→PipeWire route went through alsa-lib's pipewire plugin; the new one goes through the PulseAudio protocol. That is a behaviour change for the owner to accept.

You own `src/stdlib/Audio/Linux/**`, the Linux rows of `src/stdlib/Audio/btrc.toml` and the Linux audio tests; stay out of other packages.
