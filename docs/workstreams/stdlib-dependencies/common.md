## Common rules for every worker (read fully)

You are working in a git worktree of the `btrc` repository (a C-like language "BTRC" with a Python reference compiler and a self-hosted compiler; its standard library is in `src/stdlib`). Read `AGENTS.md` first (architecture and hard rules: camelCase names in .btrc, PascalCase .btrc file names, strict imports, never hand-edit generated files).

The owner wants the whole standard library back on first-party code plus APIs supplied by each target OS (wgpu-native is the only third-party exception). `docs/design/stdlib-dependencies.md` is the audit (generated), `tools/qualification/stdlib-dependencies.toml` its policy (what each OS supplies, `[[pending]]` rows for third-party requirements awaiting removal, `[[decisions]]` for the owner), and `python3 -m tools.qualification.dependencies check` the gate (`make stdlib-dependencies`). When your work removes a requirement, delete its `[[pending]]` row (keep the `[[dependencies]]` naming rows), run `python3 -m tools.qualification.dependencies report --write`, and make sure `check` passes. `python3 -m tools.qualification.dependencies binary --target <label> <executable>` classifies what a built program imports; use `tools.qualification.dependencies.DependencyAudit().binary_problems(path, target)` in tests to prove a removal.

### Do NOT touch
`flake.nix`, `flake.lock`, `nix/*`, `.github/workflows/*`, `Makefile`, `PLAN.md`, `AGENTS.md` — the integrator edits those after merging; list in your report the lines there that should change. Do not push; do not open PRs. Stay out of stdlib packages other workers own (named in your task).

### How to build and test
- Export `BTRC_TEST_RUNNER=linux-devcontainer` and run everything through `nix develop --command …` from the worktree root (the first run evaluates the flake; that is expected).
- Fast loop with the reference compiler: `nix develop --command bin/btrcpy path/Program.btrc -o /some/scratch/out.c` (~8 s), then `gcc -std=c11 -Wall -Wextra -Werror -pedantic-errors out.c -lm -lpthread`. If `bin/btrcpy` does not exist, run `nix develop --command make NIX= build`. A program that imports a module with native records gets a link plan beside the C file; see `src/tests/python/test_network_runtime.py::_transpile` and `tools/native_plan.py` (`NativePlanBuilder`).
- BTRC gotchas seen so far: a managed `string` cannot be passed to a C function whose parameter is `const char*`/`char*` unless the declaration is an `extern` with a `string` parameter or the binding marks it a read-only borrow (copy into a `char[]` buffer otherwise); `{}` inside an f-string is a syntax error; a nullable `T?` must be narrowed with `if (x != null)` before member access; a module no manifest exports is package-private; a provider file (`[[package.providers]]`) is implicitly imported by its module on the selected OSes.
- Pytest: `nix develop --command python3 -m pytest <test> -q -p no:cacheprovider --compilers=python`; `--compilers=both` adds the self-hosted compiler. **The self-hosted compiler is rebuilt (10–25 minutes, 3+ GB RAM) whenever any stdlib `btrc.toml` or any module the compiler imports changes**, and the machine (4 cores, 15 GB) is shared with other workers: iterate with `--compilers=python` only, batch your manifest edits, and run the `--compilers=both` pass once at the end (set `BTRC_TEST_COMPILER_CACHE=<checkout>/build/test-btrcc` so builds are shared and locked). Never run more than one heavy compile at a time; keep pytest at `-n 2` at most.
- Corpus programs live in `src/tests/<topic>/<Name>.btrc` with golden output in `expected/<Name>.stdout`; `python3 -m pytest src/tests/runner.py -q --compilers=python -k <Name>` runs them. A program that cannot build or run on some target is classified in `src/tests/fixtures/target-applicability.toml`.
- Before finishing run: `nix develop --command make NIX= lint format-check` (`make NIX= format` fixes formatting), and `python3 -m pytest src/tests/btrc/test_naming_convention_contract.py src/tests/python/test_platform_inventory.py src/tests/python/test_qualification_ledger.py src/tests/python/test_stdlib_dependencies.py src/tests/python/test_ci_workflow_contracts.py -q --compilers=python`.
- Derived files: any stdlib manifest change changes `src/stdlib/btrc.lock`; a new/removed/renamed export also changes `src/devex/lsp/catalog/generated.py` (`python3 -m tools.compiler_codegen.main generate`), possibly `src/stdlib/btrc.symbols`, and needs an inventory row per export in `docs/design/platform-inventory.toml` (six slices) followed by `python3 -m tools.register_package <Package> --refreeze`, which rewrites the lock, `tools/qualification/denominators.toml`, the counts in `docs/design/platform-parity.md` and the pins in `src/tests/python/test_qualification_ledger.py` (for a brand-new package of plain BTRC, `python3 -m tools.register_package <Package> --reason "…"` does all of it). Put these regenerated files in a **separate final commit** whose subject starts with `derived: regenerate`, so the integrator can redo it at merge time. Prefer package-private modules (not exported) for internals, which need none of this.
