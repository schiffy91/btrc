## Your piece: the Linux GUI provider without GTK 4 (first-party X11)

The Linux GUI provider (`src/stdlib/GUI/Linux/Gtk*.c`, 2,900 lines of C) implements the portable shim contract (`src/stdlib/GUI/Shim/Shim.h`, `ShimControls.h`, `ShimSurface.h`, `ShimWeb.h`; the BTRC side in `src/stdlib/GUI/Shim/*.btrc` is shared with Windows, Android and iOS) over GTK 4, and so links `gtk4`, `gtk4-wayland`, `gtk4-x11`, `wayland-client`, `x11` and, for the web view, `webkitgtk-6.0`, and bundles a generated Wayland protocol file (`Linux/Wayland/`). None of those is supplied by the operating system. Replace the provider with first-party code.

Read first: the four shim headers (they are the contract — every function and every event), `GtkShim.c`/`GtkControls.c`/`GtkCanvas.c`/`GtkSurface.c` for the behaviour each function has today, `Windows/Win32Shim.c`/`Win32Controls.c` as the other complete C implementation of the same contract, `src/stdlib/GUI/README.md`, the Linux rows of `src/stdlib/GUI/btrc.toml`, `docs/design/native-ui-gtk4-gate*` and the Linux parts of `docs/design/native-ui-*` documents, the decisions "A web view on Linux" and "The display client library a Linux GPU surface needs" in `tools/qualification/stdlib-dependencies.toml`, the tests (`src/tests/python/test_native_ui_conformance.py::test_linux_conformance_case`, `test_native_linux_providers.py`, `test_native_gui_runtime.py`, `test_native_ui2_fairness_linux.py`, `src/tests/native/gui/**`, `src/tests/python/linux_provider_fixtures.py`) and the headless tooling (`tools/ui/headless-session.sh` runs a private Xvfb or Wayland session with a window manager and real input through XTEST; `tools/headless-gate.sh`).

### Design (assume decision (a) of the display-library entry)
- **Display protocol: X11, spoken first-party over the server's socket** (`$DISPLAY` → `/tmp/.X11-unix/X<n>` or abstract socket, TCP refused; `$XAUTHORITY`/`~/.Xauthority` MIT-MAGIC-COOKIE-1). No libX11/libxcb in the link plan. Core protocol plus the extensions you need, each negotiated with `QueryExtension` and optional where a server may lack it: BIG-REQUESTS, MIT-SHM or plain `PutImage` for pictures (shared memory needs `shmget`, a libc call), XKB or core `GetKeyboardMapping` for keysyms (core mapping is enough for the keys in `BtrcShimKey`/scancodes plus text via keysym→Unicode; say what you chose), XInput2 only if smooth scrolling needs it (core buttons 4–7 otherwise), XFIXES for clipboard notifications if useful, RANDR/`Xft.dpi` resource for the scale, SYNC (`_NET_WM_SYNC_REQUEST`) for flicker-free resize if practical. ICCCM/EWMH: `WM_PROTOCOLS`/`WM_DELETE_WINDOW`, `_NET_WM_NAME`, `_NET_WM_PID`, `WM_CLASS`, `WM_NORMAL_HINTS` (minimum size), `_NET_WM_STATE` (minimised/hidden detection), `_NET_WM_PING`, clipboard and primary selections with `UTF8_STRING`/`TARGETS` and INCR for large text. A Wayland session is served through Xwayland; a session with no X server reports from `btrcShimInit` that no display can be opened (state this limit prominently in the report and the README).
- **Text entry and input methods:** the XIM protocol is large; the practical first-party route is the input method framework's own D-Bus interface (IBus: `org.freedesktop.IBus`; Fcitx 5: `org.fcitx.Fcitx5`) through the stdlib's first-party D-Bus client (`src/stdlib/DBus/` if it has landed — check; do not add libdbus), falling back to direct keysym→text (including dead keys/compose for Latin if feasible). The contract's `TEXT_EDITING` (preedit) events and `SetTextInputArea` must work when an input method is present; when none is, typing still produces `TEXT_INPUT`. Say exactly what is and is not covered.
- **Controls are drawn first-party** (GTK drew them before): button (title, centred, symbol shapes, bordered, selected, transparent), label (secondary, centred, wrapping with natural height for width), spinner, level, slider, select with a popup list (an override-redirect window with pointer/keyboard grab, candidates, dismissal by Escape or outside click), one-line text field (caret, selection by mouse and keyboard, clipboard, undo is optional, placeholder, preedit display, horizontal scrolling), picture, fill with rounded corners, scroll bar, tooltips, light and dark appearance (`btrcShimSetDarkAppearance`), focus rings and keyboard traversal exactly as the events in the contract require (`CONTROL_FOCUS_GAINED/LOST`, activation by Space/Return, slider keys, select keys). Natural sizes must be stable and sensible. Use the stdlib's first-party font face (the first-party TrueType reader/rasterizer behind `Library.GUI.FreeType`/`Font`, if it has landed — check; system font discovery without fontconfig: read `fc`-style well-known directories `/usr/share/fonts`, `/usr/local/share/fonts`, `~/.local/share/fonts`, `~/.fonts`, and NixOS's `/run/current-system/sw/share/X11/fonts`, pick a sans UI font by family preference, and say how; the C shim may call into a small first-party C rasterizer of its own only if the BTRC one cannot be reached from C — prefer one implementation) for `btrcShimRasterizeText` and control text. Anti-aliased drawing (rounded rectangles, lines, circles, triangles) is a small first-party software rasterizer writing RGBA.
- **Presentation:** `btrcShimWindowShowsPictures` is true: frames arrive as RGBA pictures (`btrcShimWindowShowPicture`) and the shim composes its controls over them (`btrcShimWindowDrawControls`), as the GTK provider did on X11. **GPU views** (`ShimSurface.h`): wgpu-native needs an Xlib `Display*` or an xcb connection plus the window id. A window id is server-global, so the first-party connection owns the window (a child window per GPU view/hole), and a second connection opened through the display client library gives wgpu-native its handle. That library is loaded only when a GPU surface is created, by `dlopen("libX11.so.6")` (or xcb — pick the one wgpu-native's surface descriptor needs the least of) behind one small first-party file, never linked; record it in the policy as part of the wgpu-native exception (`[[exceptions]]` → a `loads` entry, with a comment pointing at the decision). If the owner later refuses, GPU views on Linux go with it; keep that seam narrow.
- **Accessibility:** GTK exported an AT-SPI tree; the conformance suite reads it (find how: `pyatspi`, `tools/ui/session_evidence.py`, the catalog's accessibility cases). Provide the AT-SPI 2 D-Bus interfaces first-party over the accessibility bus (`org.a11y.Bus` → `GetAddress`; `org.a11y.atspi.Application`, `Accessible`, `Component`, `Action`, `Text`/`EditableText` for the text field, `Value` for slider/level, `Selection` for the select popup; the `org.a11y.atspi.Event.*` signals for focus, state, text and value changes; registration with the registry through `Embed`) for every control and window, through the stdlib's first-party D-Bus client. This is a large part of the work; do it after windows, input and controls pass, and report precisely which roles, states, actions and events are exported and which conformance cases depend on them.
- **Folder dialog:** `org.freedesktop.portal.FileChooser.OpenFile` with `directory=true` over the session bus (first-party D-Bus), reporting failure state 3 when no portal is present. **Message box** (`btrcShimWindowShowMessage`): a first-party modal window.
- **Web view** (`ShimWeb.h`): Linux has no system web engine; implement the functions to report "unsupported" the way the contract allows (find how other rows report a missing web view — iOS/Android/Windows all have one, so look at what `ShimWebView.btrc` does when creation fails), keep `GtkWeb.c` and the WebKitGTK records **out** of the new provider, and leave the WebKitGTK `[[pending]]` row and its decision in place (the owner decides; do not delete `GtkWeb.c` until then — instead keep it buildable only if it can stand alone, otherwise report that the web view is disabled pending the decision, with the exact tests affected).
- Language: the other providers' shims are C; a first-party C implementation under `src/stdlib/GUI/Linux/` (new files named for what they are, e.g. `X11Connection.c`, `X11Shim.c`, `X11Controls.c`, `Accessibility.c`) is consistent with them. Strict C11 (`-std=c11 -Wall -Wextra -Werror -pedantic-errors`), no GNU extensions beyond `_GNU_SOURCE` feature macros for libc, every protocol read bounded and validated (the X server and D-Bus peers are trusted more than network peers, but lengths must still be checked).

### Order of work, each step leaving the tree green for what it covers
1. X11 connection, windows, events, pictures, cursor, clipboard, timing/wake (`btrcShimPushWake` from any thread: an `eventfd`/pipe in the poll set), automation functions. Run the Linux provider tests that need no control.
2. Text rasterization and the drawn controls; placement, holes and clipping; focus and keyboard.
3. Text field editing and input methods.
4. GPU surface seam.
5. Accessibility over AT-SPI.
6. Folder dialog, message box, tooltips, polish; delete the GTK files, the Wayland directory and the gtk4*/wayland-client/x11 pkg-config records; update the policy rows (`GTK 4`, `libwayland-client`, `libX11`, the bundled viewporter row), README and design docs.

### Proving it
- `tools/ui/headless-session.sh --x11 -- …` gives a private Xvfb session with a window manager; the Linux UI conformance cases (`test_native_ui_conformance.py::test_linux_conformance_case`, both frontends at the end) and the Linux provider tests are the bar. Report the pass/fail/skip counts before (GTK, at your base commit, X11 session) and after, case by case for any that differ. The Wayland-session rows of the suite now run through Xwayland if the headless Wayland compositor provides it (labwc can); if it cannot here, say so and which rows did not run.
- `DependencyAudit().binary_problems(executable, "linux-x86_64") == []` for a GUI program without a GPU view; with a GPU view only wgpu-native and the recorded display-library load appear, and `LD_DEBUG=libs` shows no GTK, GLib, cairo, pango, harfbuzz, fontconfig, freetype, libdbus or libwayland in a run without a GPU view.
- ASan/UBSan runs of the provider tests; no leaks of X resources across 100 window create/destroy cycles (the suite has such cases).

This is the largest piece of the whole effort. Work in the order above, commit after each step, and if you run out of budget stop at a step boundary with the tree green and a precise account of what remains — do not leave a half-switched provider.
