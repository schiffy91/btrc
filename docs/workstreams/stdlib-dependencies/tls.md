## Your piece: a first-party TLS client, so `https://` on Linux needs no curl

`Library.HTTP`'s client (`src/stdlib/HTTP/`) is first-party for `http://`: `HTTPExchange.btrc` runs one HTTP/1.1 exchange over an `IHTTPByteStream`, and `Unix/HTTPPlainTransport.btrc` supplies the socket stream. On Linux and macOS `https://` still launches the `curl` process (`HTTPCurlTransport.btrc`, selected by `Unix/HTTPTransportProvider.btrc`). Windows uses WinHTTP; macOS/iOS/Android will use their system HTTP stacks. **Linux supplies no TLS**, so Linux gets a first-party TLS client in BTRC. The policy's `[[decisions]]` entry "TLS on Linux" records this for the owner; your job is to build it soundly and say plainly what it does and does not cover.

`Library.Crypto` now holds first-party primitives (read `src/stdlib/Crypto/README.md` and the package's modules: SHA-256/512, BLAKE2b, X25519, Ed25519, ChaCha20, Poly1305, OS random, wipe). Reuse them; add what TLS needs beside them in the same style (constant-time where secrets are involved; strict C11 output, no `__int128`).

### Build
1. Primitives still missing: SHA-384, HMAC and HKDF (SHA-256/384), AES-128/256 (constant-time: no secret-indexed tables — bitsliced or an arithmetic S-box), GCM with a constant-time GHASH, ChaCha20-Poly1305 AEAD in the RFC 8439 form, big-integer modular exponentiation for RSA **verification** (public operands; PKCS#1 v1.5 and PSS, SHA-256/384/512, keys 2048–8192 bits), P-256 and P-384 ECDSA **verification** (public operands). Key exchange is X25519 only (so no secret-scalar NIST-curve code is needed); state that as a limit.
2. X.509: a strict DER reader; certificates (v3), names, validity, SPKI (RSA, EC P-256/P-384, Ed25519), extensions basicConstraints, keyUsage, extendedKeyUsage, subjectAltName (dNSName, iPAddress), nameConstraints (dNSName and iPAddress permitted/excluded subtrees); reject any unknown **critical** extension. Path building from the server's chain to a trust anchor (bounded depth and bounded work, cross-signed/out-of-order/duplicated chains handled), checking every signature, validity against the system clock, CA flags and path length, key usage, EKU serverAuth when present, name constraints, minimum key sizes (RSA ≥ 2048), no MD5/SHA-1 signatures below the anchor. Host name verification per RFC 6125/9525: SAN only (no CN fallback), one left-most `*` label wildcard, never across dots or on public-suffix-like single labels, IP literals against iPAddress SANs only, case-insensitive ASCII; reject names with NUL or non-ASCII.
3. Trust anchors on Linux: `SSL_CERT_FILE`, then `SSL_CERT_DIR`, then the first that exists of `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`, `/etc/ssl/ca-bundle.pem`, `/etc/ssl/cert.pem`, then the directory `/etc/ssl/certs`. PEM parsing; a bundle that cannot be read is an error ("no trusted certificates"), never "trust everything". (These environment variables are the system convention OpenSSL-based programs honour; they are how the tests supply a per-run CA.)
4. TLS 1.3 client (RFC 8446): X25519 key share; suites TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256; signature schemes ecdsa_secp256r1_sha256, ecdsa_secp384r1_sha384, rsa_pss_rsae_sha256/384/512, ed25519 (plus rsa_pkcs1_* for certificate signatures only); SNI, ALPN `http/1.1`, supported_versions, HelloRetryRequest, middlebox-compatibility (legacy session id, tolerate one dummy ChangeCipherSpec), record size limits, KeyUpdate, NewSessionTicket ignored (no resumption, no 0-RTT, no PSK), no client certificate (send an empty Certificate if asked), alerts sent and received, close_notify; a transport end without close_notify is a truncation error the HTTP layer must see when the body is close-delimited. Downgrade sentinel check in ServerHello.random.
5. TLS 1.2 client (RFC 5246/7627/7905) for servers without 1.3: ECDHE (x25519 only) with RSA or ECDSA authentication and AEAD suites only (AES-128-GCM-SHA256, AES-256-GCM-SHA384, CHACHA20-POLY1305-SHA256); extended master secret required; renegotiation_info sent and renegotiation refused; no CBC, no RSA key transport, no compression, no session tickets. If you cannot finish 1.2 soundly, leave it out, make the client 1.3-only, and say so prominently in the report (a gap for the owner).
6. Shape: a `TLSClient`/`TLSStream` (module names yours) that takes a connected byte stream (define a small interface or reuse `IHTTPByteStream`; do not make Crypto depend on HTTP), a server name, a deadline and a trust store, and exposes `receive`/`send`/`close` with the same deadline discipline as `HTTPSocketStream`. Put TLS and X.509 in their own stdlib package (e.g. `src/stdlib/TLS/`, registered with `tools.register_package`), with a README stating scope, limits and "first-party and unaudited".
7. Wire it into `Unix/HTTPTransportProvider.btrc` for **linux** (`https://` → socket → TLS → `HTTPExchange`). macOS keeps the interim curl path for now through a separate provider file selected for macos (it will move to NSURLSession), so the `curl` pending row narrows to `os = ["macos"]`. Update the policy, audit document and `docs/design/platform-inventory.toml` reasons accordingly.

### Hostile-input discipline
Every length, count and offset from the peer is bounded before use (handshake message ≤ a stated cap, certificate chain ≤ 10 certificates and ≤ 64 KiB each or similar stated caps, record ≤ 2^14 + 256); every parse fails closed; decrypt failures, unexpected messages and bad signatures abort with an alert and an error, never a partial result; secrets are wiped; comparisons of MACs/Finished are constant-time; the transcript hash and state machine admit only the messages legal in each state. No verification can be switched off: there is no "insecure" option and no environment variable that disables checking.

### Proving it
- Known answers that stay in the corpus (pure BTRC, every target): FIPS/NIST vectors for SHA-384, HMAC, HKDF (RFC 5869), AES and GCM (NIST SP 800-38D test cases), RFC 8439 AEAD, RFC 8448 TLS 1.3 key-schedule traces, RSA PKCS#1/PSS and ECDSA P-256/P-384 verify vectors (generate with the dev shell's `openssl` and hard-code; include invalid-signature and malleability negatives, and Wycheproof-style edge cases you can construct: r or s = 0, ≥ n, wrong curve point, non-canonical DER).
- A pytest driver (both frontends at the end, gcc and clang, plain and ASan/UBSan) with a per-run CA made by the dev shell's `openssl` CLI and real servers: `openssl s_server` for each TLS 1.3 suite and each certificate type (RSA 2048, RSA-PSS if you support its SPKI, ECDSA P-256, ECDSA P-384, Ed25519), TLS 1.2-only servers for each 1.2 suite, HelloRetryRequest (server restricted to a group you did not offer first, if any), KeyUpdate, large bodies in both directions, many small records. Python's `ssl` module may also serve. Negative cases, each asserting a specific error and **no bytes delivered to the HTTP layer**: untrusted root, expired, not yet valid, wrong host, SAN missing (CN only), wildcard misuse, intermediate without CA flag, path length exceeded, name-constraint violation, EKU without serverAuth, weak RSA key, SHA-1-signed leaf, corrupted CertificateVerify/Finished and flipped ciphertext bits (a small byte-flipping TCP proxy in Python), truncation without close_notify, TLS 1.1-only and CBC-only servers refused, a server that selects a suite or group that was not offered.
- End to end through `HTTPClient` against an HTTPS server on loopback with PATH emptied (no curl reachable), and `DependencyAudit().binary_problems(executable, "linux-x86_64") == []` on the built program. Update `src/tests/stdlib/HttpClientLocal.btrc` (it exercises the interim curl stand-in with an `https://` URL) so it still tests what remains of the curl path only where a row still selects it, or retire it for Linux with the applicability file updated.
- Robustness: feed the DER/X.509 parser and the record/handshake parsers truncated and bit-flipped inputs under ASan/UBSan; no findings, no hangs.

Stay out of `src/stdlib/GUI`, `Image`, `Tray`, `Bluetooth`, `Audio` (other workers).
