## Your piece: a first-party matcher in place of the bundled musl regex/glob/fnmatch

`src/runtime/windows/musl/` is musl's TRE regex, `glob.c` and `fnmatch.c`, bundled so that `Library.Regex`, `Library.Pattern` and glob build on the Windows rows (`src/runtime/windows/regex.h`, `fnmatch.h`, `glob.h` compile it into the including unit; read `src/runtime/windows/README.md`). On every other target those names come from the system's C library, which is an OS API. Bundled third-party source is not allowed: replace it with first-party code and delete the directory.

Read first: `src/stdlib/Regex.btrc`, `src/stdlib/Pattern.btrc`, every use of `regcomp`/`regexec`/`regerror`/`regfree`/`fnmatch`/`glob` in `src/stdlib` and the compiler (`grep -rn "regcomp\|regexec\|fnmatch(\|glob(" src tools --include=*.btrc --include=*.c --include=*.h --include=*.py -l`), the tests under `src/tests/native/posix_matching/` and the Python tests that drive them, `src/language/hosted_abi.toml` (the hosted names), and the `[[bundled]]`/`[[pending]]` rows for musl in `tools/qualification/stdlib-dependencies.toml`.

Decide the layer by what keeps behaviour the same for existing callers:
- Preferred: first-party implementations of the same POSIX interfaces for the Windows overlay only (`regcomp`, `regexec`, `regerror`, `regfree` with `REG_EXTENDED`, `REG_ICASE`, `REG_NOSUB`, `REG_NEWLINE`, `REG_NOTBOL`, `REG_NOTEOL` and POSIX leftmost-longest matching with sub-match reporting; `fnmatch` with `FNM_PATHNAME`, `FNM_NOESCAPE`, `FNM_PERIOD` and the flags the tests use; `glob`/`globfree` with the flags used), written from the POSIX specification, in strict C11, in first-party files under `src/runtime/windows/`. POSIX rows keep their system libc, so nothing changes there.
- The engine must be safe on hostile patterns and inputs: no exponential backtracking (a Thompson/Pike simulation with POSIX leftmost-longest sub-match priority, or a backtracker with a proven bound), bounded memory, bracket expressions with ranges and the POSIX classes (`[:alpha:]` …), anchors, alternation, grouping, intervals `{m,n}` (bounded by RE_DUP_MAX 255), back-references in BRE only if any caller or test needs them (check; if none does, refuse them with `REG_ESUBREG`/`REG_BADPAT` and say so). ASCII/C-locale semantics are acceptable if that is what the musl overlay gave (check `locale_impl.h` use); state what you chose.
- Write it yourself from the specification. Do not copy or translate musl, TRE, glibc, BSD or any other existing implementation.

### Proving it
- A differential harness against the **host libc** on Linux (glibc's `regcomp`/`regexec`/`fnmatch`): compile your implementation natively under different symbol names and compare results and sub-match offsets over a large generated set of patterns × subjects (ERE and BRE, all flags), plus the existing posix_matching tests' cases. Report the mismatches and classify each (glibc extensions such as `\w`, `\b`, `\<` are not POSIX: decide by what the old musl overlay did — build the old overlay natively the same way and use it as the second reference, since *it* is the behaviour Windows callers had).
- Fuzz for crashes and time bounds under ASan/UBSan (pathological patterns like `(a*)*b`, `(a|aa)*c`, deep nesting, long bracket lists) and assert linear-ish time.
- The existing Windows tests for these names (cross-built with zig; see how `src/tests/python/test_windows_*.py` and `src/tests/native/posix_matching` build and what runs only on a real Windows runner) must build for `windows-x86_64` and `windows-aarch64` through both frontends. Say exactly what could only be cross-built here and needs the Windows CI job to run.
- Remove the musl `[[bundled]]` and `[[pending]]` rows, the `COPYRIGHT` file and every mention that the overlay is musl; `python3 -m tools.qualification.dependencies check` must pass and the audit document must be regenerated.

`src/runtime/**` is normally the integrator's; for this task you own `src/runtime/windows/{regex.h,fnmatch.h,glob.h,musl/}` and their replacements, and nothing else under `src/runtime`. If a runtime boundary fixture (`src/tests/fixtures/compiler_boundaries/manifest.toml`, `make test-boundaries`) records these files, re-capture it with the repo's tool and say so in the report.
